The module is organized as a flat package of contracts plus a `metrics/` sub-package of stateless KPI helpers. At the top level, `result.py` declares the canonical `DiagnosticResult` Pydantic model together with `DiagnosticStatus` and `Severity` enums that every diagnostic producer must return; `engine.py` provides `DiagnosticEngine`, which aggregates a list of `DiagnosticResult`s into summaries, failure lists, and human-readable findings. Two parallel observation models define the remote boundary: `observation.py` holds the local `ObservationContext` (used by CLI/local collectors) while `remote_observation.py` defines the stricter `RemoteObservationContext` and `AgentObservation` envelope sent over the wire, enforcing timezone-aware timestamps and requiring `confidence` to match `evidence_quality`. The `metrics/` sub-package exposes pure functions grouped by domain — bandwidth conversion (`bandwidth.py`), congestion scoring/state (`congestion.py`), RFC-compliant jitter and latency summarization (`latency_jitter.py`), loss percentage and severity classification (`loss.py`), and throughput/utilization math (`throughput.py`) — re-exported through `metrics/__init__.py` so callers import from `core.metrics` only. Dependency direction is strictly inward: metrics depend on nothing in `core/`; `remote_observation.py` depends on `observation.py` and `result.py`; `engine.py` depends only on `result.py`.
