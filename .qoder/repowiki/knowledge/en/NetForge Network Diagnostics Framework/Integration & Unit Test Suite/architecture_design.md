Tests are organized as flat pytest modules under `tests/`, each targeting a subsystem: HTTP endpoints (`test_agent_http.py`, `test_controller_http.py`) spin up in-process `ThreadingHTTPServer` instances to exercise real handlers; service-layer tests (`test_agent_service.py`, `test_controller_service.py`) instantiate `AgentService`/`ControllerService` with in-memory or `tmp_path`-backed stores and fake dispatchers; analysis/rule tests (`test_rules.py`, `test_baselines.py`) feed `AnalysisContext` of `DiagnosticResult` into `RuleEngine` and individual rules; pure-function tests live in `test_metrics.py`; data-persistence behavior is covered by `test_path_flow_storage.py` and `test_observation_contract.py`. The `examples/` directory holds static JSON fixtures (`flows_sample.json`, `mesh_topology.json`) consumed by tests that validate flow parsing and mesh graph construction. There is no shared test harness — each file imports directly from the package's `agent`, `controller`, `analysis`, `core`, and `storage` modules.
