The `engine.RuleEngine` is the central orchestrator: it loads a registry of `DiagnosticRule` subclasses from `analysis.rules`, executes each rule's `evaluate(ctx)` against a shared `AnalysisContext` built from raw `DiagnosticResult`s, collects all `DiagnosedIssue` outputs, applies conflict/subsumption resolution via `suppressed_rules`, sorts by `Severity` then `Confidence`, and assembles a `DiagnosisReport`. Rules are isolated per layer (baseline, dns, flow, gateway, host, link/link_domain, mesh, path, transit, transport) under `rules/`, each implementing the abstract `DiagnosticRule` interface in `rule.py`. Cross-cutting contracts — `DiagnosedIssue`, `Recommendation`, `ConfidenceLevel`, and `DiagnosisReport` models in `models.py`, plus the read-only `AnalysisContext` in `context.py` — define how rules observe probe data and how the engine aggregates findings. The engine also captures per-rule exceptions into `rule_errors` so one failing rule cannot crash the full analysis pipeline.
