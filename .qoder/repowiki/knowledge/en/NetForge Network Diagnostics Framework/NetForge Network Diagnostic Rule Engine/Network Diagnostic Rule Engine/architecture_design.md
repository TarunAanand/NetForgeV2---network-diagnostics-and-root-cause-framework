The module is organized around four cooperating layers. `engine.py` defines the `RuleEngine`, which owns a list of `DiagnosticRule` implementations (loaded from `analysis.rules.DEFAULT_RULES`) and orchestrates the pipeline: evaluate each rule against an `AnalysisContext`, collect raw issues, filter suppressed rules, sort by severity/confidence, compute overall status, synthesize a verdict, and assemble a `DiagnosisReport`. `context.py` provides `AnalysisContext`, an indexed cache over `core.result.DiagnosticResult` observations grouped by module (`interface`, `routing`, `gateway`, `connectivity`, `dns`, `packet_loss`, `latency`, `resource_network`, `link_utilization`, `traceroute`, `path_change`) that exposes high-level queries per OSI layer. `rule.py` defines the abstract `DiagnosticRule` base class with shared metadata (`rule_id`, `name`, `category`) and a `build_issue` helper that normalizes confidence into `ConfidenceLevel`. `models.py` declares Pydantic data models (`ConfidenceLevel`, `Recommendation`, `DiagnosedIssue`, `DiagnosisReport`) used as the engine's output contract. `formatter.py` renders a `DiagnosisReport` to a Rich console with color-coded panels for status, issues, evidence, and recommended actions. `__init__.py` re-exports the public API surface. Dependency direction is one-way: engine → context + rule + models; formatter depends only on models; rules depend on context and models — no reverse dependencies exist.
