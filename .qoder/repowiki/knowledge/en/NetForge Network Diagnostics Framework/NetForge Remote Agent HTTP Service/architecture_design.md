The module is organized as a thin transport layer over reusable business logic:
- `__main__.py` parses CLI args (`--host`, `--port`) and bootstraps the service.
- `config.py` defines a frozen `AgentConfig` dataclass loaded from environment variables (`NETFORGE_AGENT_ID`, `NETFORGE_AGENT_TOKEN`, `NETFORGE_ALLOWED_TARGETS`, `NETFORGE_TAG_*`), providing agent identity, auth token, allowed targets, and topology tags.
- `models.py` declares Pydantic `ProbeRequest` and a `ProbeType` enum plus a `TARGETED_PROBES` whitelist used for target authorization.
- `service.py` contains `AgentService`, which performs Bearer-token HMAC comparison, enforces allowed-target policies, dispatches probe types to `diagnostics.host.*` and `diagnostics.path.traceroute` modules, and wraps results into `AgentObservation` objects with `RemoteObservationContext` and `EvidenceQuality` metadata.
- `http_server.py` builds a minimal `BaseHTTPRequestHandler` subclass via `make_handler`, mounting three endpoints under `/v1/health`, `/v1/inventory`, `/v1/probe`; it serializes responses to JSON and maps `AuthorizationError`, `TargetNotAllowedError`, and Pydantic `ValidationError` to appropriate HTTP status codes. The HTTP layer depends on `service` and `models`, while `service` depends only on configuration and shared `core.*` / `diagnostics.*` packages — no circular imports between transport and business logic.
