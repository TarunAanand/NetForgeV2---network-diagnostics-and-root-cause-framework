Two cooperating modules form a thin storage layer on top of SQLite. `history.py` defines the `HistoryStore` class which owns a single SQLite database (path from `NETFORGE_HISTORY_DB`, defaulting to `.netforge_history.db`) and exposes CRUD operations: `save_snapshot` writes JSON payloads with timestamps, `latest_snapshot`/`previous_snapshot` retrieve recent entries, and `rolling_baseline` computes the mean of a numeric metric across the last N snapshots. The schema is created lazily via `_ensure_schema` using `CREATE TABLE IF NOT EXISTS` plus an index on `(domain, key, created_at DESC)`. `baselines.py` builds on this by providing `record_and_compare`, which persists a new sample and compares it against the rolling baseline to produce a `DiagnosticResult` with status/severity derived from configurable `warn_ratio`/`fail_ratio` thresholds and a `higher_is_worse` flag. `compare_probe_metrics` maps upstream diagnostic results from `latency`, `packet_loss`, and `link_utilization` modules into baseline comparisons under shared domain/key namespaces (`host:latency:...`, `host:loss:...`, `link:util:...`). Dependency direction is one-way: `baselines.py` imports `HistoryStore` from `history.py`; there are no external framework dependencies beyond stdlib `sqlite3` and `json`.
