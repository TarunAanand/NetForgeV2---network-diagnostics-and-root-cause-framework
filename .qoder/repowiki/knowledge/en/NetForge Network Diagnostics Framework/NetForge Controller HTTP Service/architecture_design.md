Single-process Python service launched via `python -m controller` (`__main__.py`) that wires together four layers with clear dependency direction: (1) HTTP presentation in `http_server.py` — a `ThreadingHTTPServer` with a dynamically created `BaseHTTPRequestHandler` subclass validates a Bearer token via `hmac.compare_digest` and dispatches GET/POST routes under `/v1/*`; (2) orchestration layer in `service.py` — `ControllerService` owns business logic (agent registration, job fan-out, status computation) and depends only on the store and dispatcher; (3) outbound dispatch in `dispatch.py` — `AgentDispatcher` uses a bounded `ThreadPoolExecutor` to call each registered agent's `/v1/probe` endpoint concurrently, collecting observations and errors; (4) persistence in `store.py` — `ControllerStore` wraps a single SQLite file (`agents`, `jobs` tables) with schema auto-created on init. Configuration is read from environment variables into a frozen dataclass (`config.py`). Models are Pydantic v2 `BaseModel`s shared across layers. The service depends outward on `agent.models.ProbeRequest` and `core.remote_observation.AgentObservation` but exposes no internal APIs beyond its constructor.
